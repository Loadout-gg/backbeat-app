# Artists directory

Mode: Operate.

## Job and authority
Agency operators find a workspace artist, open the profile and reach the existing edit workflow. Large desktop is primary; narrow layouts are regressions, not a new performer-facing product.

The Artists panel in the supplied Agent Artists flow board establishes a searchable table, stage/real-name hierarchy, genres, location, fee, actions and a paginated footer. M3's current shell and Obra-aligned neutral tokens remain the styled authority. Role annotations, CSV, deletion and event metrics in the board do not authorize their implementation.

## Measured baseline
On the unchanged M4 local deployment, a real Chrome search for one unique artist retained all 205 synthetic rows. The page also advertises pagination without slicing the rows. Long names force later columns into the existing table's horizontal overflow. Stored zero fee and hardcoded zero event counts are misleading presentation states.

## Direction
Preserve one page-owned sr-only Artists h1 and use a labelled search, clear action, explicit A–Z context, a quiet table and a real range/pagination footer. Keep Add artist primary and Edit in an artist-specific keyboard menu. Use fixed readable type, a centered directory surface capped at 100rem, bounded column measures and wrapping names/locations; do not spread short values across unlimited 4K space or hide columns to eliminate overflow. At narrow widths, make any table scroll region keyboard-focusable and named; portal menus must escape that container.

## Truth and privacy
Search the full approved directory snapshot, not only the visible page. Search includes all genres even when the row displays a shorter genre summary. Counts and ranges describe real matches. Empty roster, no matches and read failure are different states. CSV/Delete are unavailable, event count is not fabricated and zero fee differs from missing fee. The client receives only directory-display data, never hidden contacts, documents, free notes or health fields. This slice does not change artist writes or booking semantics.

## Verification
Observe behavioral RED/GREEN before implementation. Verify all rows across a multi-page roster and find an artist beyond the reader's first data batch; maintain workspace isolation. Exercise search/clear/reset, keyboard menus and pagination, Edit persistence and profile navigation. Inspect actual DPR1 1440×960, 1920×1080, 2560×1440, 2560×1600, 3840×2160, 1024×768, 390×844 and 320×800, plus 1920×1080 CSS at DPR2. Finish with real local regressions, source/runtime equivalence and exact code/pixel reviews. No physical-monitor or whole-product accessibility claim.
